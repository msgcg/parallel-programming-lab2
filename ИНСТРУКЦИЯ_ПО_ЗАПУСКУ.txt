1. СУТЬ И АРХИТЕКТУРА РАБОТЫ:
--------------------------------------------------------------------------------
Лабораторная работа демонстрирует многопоточность в Java двумя способами:
1. Графическое приложение (Swing GUI):
   - Потоки создаются двумя стандартными путями:
       * Наследование от java.lang.Thread (ComputeRects, ComputeOvals);
       * Реализация интерфейса java.lang.Runnable (ComputeLines).
   - Объединение потоков в общую группу ThreadGroup ("DrawingThreadsGroup")
     для централизованного управления жизненным циклом.
   - Управление приоритетами через Thread.setPriority() (MIN_PRIORITY, NORM_PRIORITY,
     MAX_PRIORITY). Поток с более высоким приоритетом получает больше квантов
     времени процессора и генерирует больше фигур (видно по счетчикам).
   - Синхронизация: отрисовка и обновление счетчиков передаются в диспетчерский
     поток AWT EventQueue (EDT) через SwingUtilities.invokeLater() для предотвращения
     гонок отрисовки (Thread Interference).
2. Многопоточный бенчмарк параллельного вычисления (CLI):
   - Параллельное вычисление математического выражения на массиве из 40 000 000 элементов.
   - Измерение времени выполнения при 1, 2, 4, 8 потоках.
   - Демонстрация ускорения вычислений на многоядерном процессоре (Закон Амдала).

4. ТИПОВЫЕ ВОПРОСЫ ПРЕПОДАВАТЕЛЯ (В. И. СТЕПАКОВА) И ОТВЕТЫ:
--------------------------------------------------------------------------------
В: В чем разница между наследованием от Thread и реализацией Runnable?
О: Наследование от Thread связывает класс с единственной цепочкой наследования Java
   (в Java множественное наследование классов запрещено). Реализация интерфейса
   Runnable отделяет задачу от механизма выполнения, позволяет классу наследоваться
   от другого базового класса (например, JPanel) и лучше подходит для работы
   с пулами потоков (ExecutorService).

В: Почему Swing требует обновления через SwingUtilities.invokeLater()?
О: Библиотека Swing является однопоточной: за отрисовку и события отвечает
   выделенный Event Dispatch Thread (EDT). Прямое обращение к GUI-компонентам
   из сторонних потоков вызовет повреждение внутреннего состояния и артефакты экрана.

В: Почему при увеличении числа потоков с 2 до 8 в бенчмарке время может не уменьшаться?
О: Эффект насыщения вычислительных ядер процессора: на 2 физических ядрах процессор
   обеспечивает реальный параллелизм для 2-4 потоков. Дальнейшее увеличение числа
   потоков (до 8) приводит к накладным расходам на переключение контекста
   (Context Switching), конкуренции за кэш L1/L2/L3 и пропускную способность памяти.
